  H14: Manually Test a Smoobu Webhook                                                                                        
  Your webhook endpoint: https://lbxw32g7v8.execute-api.us-east-1.amazonaws.com/staging/api/webhooks/smoobu               
  
  How authentication works: The handler checks the x-smoobu-webhook-secret header against SMOOBU_WEBHOOK_SECRET in Secrets
   Manager. There's no HMAC — it's a plain shared secret comparison.

  ---
  Step 1 — Confirm the secret is set in Secrets Manager

  Before testing, make sure the Smoobu webhook secret was seeded. Log in to AWS Console → Secrets Manager → find
  kalawala-staging-smoobu-webhook-secret (or similar) → verify it has a real value (not the Terraform placeholder).       

  ▎ If it's still a placeholder, set it now to any strong random string (e.g. openssl rand -hex 32). Note the value —     
  ▎ you'll need to enter it in Smoobu too.

  ---
  Step 2 — Configure the webhook in the Smoobu dashboard

  1. Log into app.smoobu.com → Settings (gear icon) → API tab
  2. Look for Webhooks section
  3. Set the Webhook URL to:
  https://lbxw32g7v8.execute-api.us-east-1.amazonaws.com/staging/api/webhooks/smoobu
  4. Set the Shared secret (or "API secret"/"Secret key") field to the exact value you stored in Secrets Manager in Step 1
  5. Subscribe to events: newReservation, cancelReservation, updateReservation, updateRates
  6. Save

  ---
  Step 3 — Send a test delivery from Smoobu

  Smoobu's API doesn't have a "test webhook" button in the dashboard UI — you'll do this with a curl call simulating what 
  Smoobu sends.

  Open a terminal and run:

  curl -X POST \
    https://lbxw32g7v8.execute-api.us-east-1.amazonaws.com/staging/api/webhooks/smoobu \
    -H "Content-Type: application/json" \
    -H "x-smoobu-webhook-secret: YOUR_SECRET_HERE" \
    -d '{"action":"updateRates","data":{"apartmentId":123}}'

  Expected response:
  {"received":true,"action":"updateRates","cache":{"invalidatedEntries":0}}

  This tests the fast path (no DB needed). If you get a 401, the secret doesn't match. If you get a 500, check Lambda     
  logs.

  ---
  Step 4 — Test a reservation action (with DB)

  curl -X POST \
    https://lbxw32g7v8.execute-api.us-east-1.amazonaws.com/staging/api/webhooks/smoobu \
    -H "Content-Type: application/json" \
    -H "x-smoobu-webhook-secret: YOUR_SECRET_HERE" \
    -d '{"action":"newReservation","data":{"reservationId":9999999,"apartmentId":123}}'

  Expected response:
  {"received":true}

  ---
  Step 5 — Verify in CloudWatch

  1. AWS Console → CloudWatch → Log groups → /aws/lambda/kalawala-staging-webhooks
  2. Look at the most recent log stream
  3. You should see structured JSON log entries with "action":"smoobu.webhook.updateRates" and
  "action":"smoobu.webhook.newReservation"
  4. Confirm no ERROR lines

  ---
  Step 6 — Test the auth rejection

  curl -X POST \
    https://lbxw32g7v8.execute-api.us-east-1.amazonaws.com/staging/api/webhooks/smoobu \
    -H "Content-Type: application/json" \
    -H "x-smoobu-webhook-secret: wrong-secret" \
    -d '{"action":"updateRates"}'

  Expected: HTTP 401. CloudWatch should log a smoobu_webhook_auth_failure alert.
